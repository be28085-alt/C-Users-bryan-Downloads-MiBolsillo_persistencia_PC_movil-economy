# Working rules for this project

- Implement and verify user-facing changes in both PC (`desktop.html`) and mobile (`mobile.html`). Keep equivalent features and financial results in both versions.
- The active controllers are `src/utils/desktop.js` and `src/utils/mobile.js`. `legacy/` contains previous web, modular and console implementations; `qt_app/` is an independent legacy application. Do not load archived modules from the active pages.
- Prefer shared domain and view modules for features used by both interfaces. Preserve the separation between Finanzas Personales and Mi Negocio.
- Persist every application data change (create, edit, delete, payments, inventory, profile, settings and restore) automatically through the shared storage layer to SQLite when running the SQLite-backed app. Apply this requirement to all future features in both PC and mobile. Report success only after the database confirms the write; show failures and preserve recovery options. Never silently fall back to browser storage after a SQLite connection or write failure. Verify persistence after reload for affected flows. Static web and the current Android package still use browser storage until their SQLite integration is implemented; do not describe those modes as SQLite-backed. Source-code edits are saved in project files, not in the financial database.
- Run `node --test tests/*.test.cjs`, `node test_shared.js` and `node test_dates.js` for changes to financial logic. For interface changes, also verify the affected flow in PC and mobile.
